# SQL Data Layer & Staging Documentation

This folder contains the mock application database schema, test dataset, RDD metadata tables, and SSRS report staging stored procedures for Epicor Kinetic lab drills.

Target engine: Microsoft SQL Server 2016+

---

## 1. Execution Order & Files in this Directory

Scripts must be executed in order:

1. **`01-erp-app-schema.sql`** (Run First):
   - Targets the `[ErpLab]` database (creates `ErpLab` if it does not exist, then switches context via `USE [ErpLab]`).
   - Creates the `[Erp]` schema and core application tables: `Company`, `Customer`, `ShipTo`, `Part`, `PartPlant`, `PartWhse`, `OrderHed`, `OrderDtl`, `OrderRel`, `ShipHead`, `ShipDtl`, `InvcHead`, `InvcDtl`, and `LabConstants`.
   - Seeds realistic order lifecycles, delivery releases, shipments, and customer invoices across companies `MFG01` and `MFG02`.
   - Re-runnable: drops child tables first using `OBJECT_ID` checks (no `DROP ... IF EXISTS`).

2. **`02-erp-rpt-staging.sql`** (Run Second):
   - Targets the `[ErpReporting]` database (creates `ErpReporting` if it does not exist, then switches context via `USE [ErpReporting]`).
   - Installs `dbo.StagedReportRun` and the stored procedure `dbo.usp_StageEpicorReport`.
   - References application tables via three-part naming `[ErpLab].[Erp].[TableName]`.
   - Dynamically builds each staged table's column list from `dbo.RddColumn WHERE Exclude = 0` using `QUOTENAME` on every column and table name.

3. **`03-rdd-definitions.sql`** (Run before executing `dbo.usp_StageEpicorReport`):
   - Auto-generated by [`engines/report/generate_rdd_sql.py`](../engines/report/generate_rdd_sql.py) from [`engines/report/*.json`](../engines/report).
   - Creates `dbo.RddTable`, `dbo.RddColumn (RddId, TableName, ColumnName, Exclude bit, ColumnOrder int)`, and `dbo.RddRelationship` in `[ErpReporting]`.
   - Installs `dbo.usp_SetRddExclude(@RddId, @TableName, @ColumnName, @Exclude)` as the learner's SQL stand-in for RDD Maintenance until the console exists.
   - Seeds the base RDD definitions where every column a lab adds (`CustPartNum`, `OrderNum_ProjManager_c`, `RevisionNum`, `ExtWeight`, `RemitToName`, `RemitToAddress1`, `RemitToCity`, `RemitToState`, `RemitToZip`, `ShipToPONum_c`, and `Weight`) has `Exclude = 1` by default. Un-excluding a column via `dbo.usp_SetRddExclude` affects only subsequent staging runs (Approved Default 20).

| [`01-erp-app-schema.sql`](01-erp-app-schema.sql) | Core ERP tables, relational keys, user-defined (`_c`) columns, and seeded data. | `[ErpLab].[Erp]` |

## 2. Lab Constants & Fixed Reference Date

To ensure all date-based queries, aging reports, and backlog analyses are reproducible without depending on system clock changes:

- **Reference Date Table**: `Erp.LabConstants`
- **Constant**: `FixedLabDate = '20261015'` (`ConstantDate = '2026-10-15'`)
- **Rule**: Queries and drills evaluate open and late orders against `FixedLabDate` (or a specified parameter), never `GETDATE()`.

## 3. Seed Data Structure

The seed dataset in `01-erp-app-schema.sql` models realistic ERP business activity across two operating companies (`MFG01` and `MFG02`):

- **Order Lifecycles**:
  - Each company contains 150 sales orders (`10001`–`10150` in `MFG01`; `20001`–`20150` in `MFG02`) spanning fully shipped and invoiced orders (`10001`–`10060`), partly shipped orders (`10061`–`10100`, which have both Line 1 and Line 2), and fully open orders (`10101`–`10150`).
  - Shipments (`Erp.ShipHead` / `Erp.ShipDtl`) use `PackNum` `50001`–`50100` for `MFG01` and `60001`–`60100` for `MFG02`.
  - Invoices (`Erp.InvcHead` / `Erp.InvcDtl`) use `InvoiceNum` `90001`–`90100` for `MFG01` and `80001`–`80100` for `MFG02`.
  - Across open and partly shipped orders, 30 orders per company have an order header `NeedByDate` earlier than the fixed lab date (`2026-10-15`).
  - Header totals (`OrderHed.OrderAmt` and `InvcHead.InvoiceAmt`) match the exact sum of detail lines.

- **Multi-Company Data**:
  > Default chosen for the lab, not confirmed against Epicor.
  - Internal customer integer identifiers (`CustNum` 1–23) exist in both `MFG01` and `MFG02` representing different commercial accounts, while both companies also share customer identifier codes `CUST01`–`CUST05`.

- **Customer Identifiers**:
  - Selected customer accounts feature numeric-string customer IDs (`CustID`), alongside standard alphanumeric codes.

- **Multi-Release Scheduling**:
  - Selected open and partly shipped order lines have multiple delivery releases (`OrderRel`) with staggered request dates (`ReqDate`).

*(Detailed record mappings, collision sets, and seed keys are documented in the git-ignored internal catalog at `answers/seed-catalog.md`.)*

## 4. SSRS RDD Staging Design & Linked Field Placement

> Default chosen for the lab, not confirmed against Epicor.
> Linked columns reside on the table containing the link key.

In Epicor Kinetic Report Data Definitions (RDD), linked tables expose description or UD fields following the naming convention `<LinkKey>_<Field>` (`[S12, S16]`).

1. **PackSlip Form**:
   - `ShipHead_<GUID>`: Holds shipment header attributes (`PackNum`, `CustNum`, `ShipDate`, `ShipStatus`, and `Weight`, which is `Exclude = 1` in base RDD and un-excluded in Lab R6 D4).
   - `ShipDtl_<GUID>`: Holds `OrderNum` (the link key to `OrderHed`), plus `CustPartNum` (`Exclude = 1` in base RDD, un-excluded in Lab R1) and `OrderNum_ProjManager_c` (`Exclude = 1` in base RDD, un-excluded in Lab R2).
2. **OrderAck Form**:
   - `OrderHed_<GUID>`: Is the parent order header table. It directly contains `ProjManager_c` as a native table column.
   - `OrderDtl_<GUID>`: Holds `PartNum` (the link key to `Part`), plus `RevisionNum` and `ExtWeight` (`Exclude = 1` in base RDD, un-excluded in Lab R3). It carries `PartNum_SteelGauge_c` and `PartNum_PPAP_c`.
   - `OrderRel_<GUID>`: Holds order release rows including `RelHoldReason_c`.
3. **ARForm Form**:
   - **Standing Question (e) Per-Client Check**: On any client engagement, verify in **Field Help > Technical Details** (*Default chosen for the lab, not confirmed against Epicor*) and the client's `ARForm` RDD which table and columns store the Remit-To block and Ship-To PO.
   - `InvcHead_<GUID>`: In this lab, `Erp.InvcHead` holds the remit-to block fields (`RemitToName`, `RemitToAddress1`, `RemitToCity`, `RemitToState`, `RemitToZip`) and the UD column `ShipToPONum_c` (Approved Default 19), all with `Exclude = 1` in the base RDD and un-excluded in Lab R4.
   - `InvcDtlShipTo` relationship: Added by the learner in Lab R4 linking `InvcDtl` (`T2`) to `ShipTo` (`T4`) on `Company`, `ShipToCustNum = CustNum`, `ShipToNum = ShipToNum` (`[S17]`).
4. **OpenOrders BAQ Report (R5)**:
   - Built via the **BAQ Report** route ([`docs/reference/04-cloud-rules.md`](../docs/reference/04-cloud-rules.md) §2.2 `[C1, S26, S27]`).
   - Staged tables: `BAQReportResult_<GUID>` (`[S26, S27]`) with `<Table>_<Field>` column names (`[B18]`) and `Calculated_DaysLate` (computed against `Erp.LabConstants` `FixedLabDate = '2026-10-15'` using `OrderHed.NeedByDate`), plus `RptLabels_<GUID>`.
